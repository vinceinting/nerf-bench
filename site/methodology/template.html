Methodology

This page says how every result on this site is produced, and what no outside benchmark can rule out. It is published before the first public result.

How a run is made

Every run installs the vendor's official app on a fresh, throwaway GitHub-hosted machine, with the vendor's default settings and nothing added: no instruction files, add-ons, hooks or scripts. Each run carries a signed attestation that binds its result file to the official workflow at a published commit of the public repository.

A run differs from a fresh install in exactly two ways, and every run record states both:

  • commands auto-approved: the agent's commands run without a person approving each one, because the machine is sealed and discarded after the run.
  • web access blocked: the agent cannot reach the internet during the run.

The tasks

Each run is a set of roughly 50 to 100 real coding tasks taken from bug fixes in open-source projects, merged after the model's published knowledge cutoff. Each task passes or fails on an automatic check. No person and no AI model grades anything.

The current task set is kept hidden from the public and from training data. A fingerprint of each set is published before its first result, and anyone can recompute it once the set retires.

A determined contributor can read the current task set. Contributors run the benchmark in their own copy of the project, under their own account, and can read what runs there. That is why the sets rotate faster than they otherwise would.

The signature still prevents faked results. Reading the tasks does not let anyone forge a result: only a run of the official, unmodified workflow produces a result whose signature verifies, and the site accepts nothing else.

Rotation

Task sets rotate every {{INTERVAL}} days. For {{OVERLAP}} days the outgoing and incoming sets both run, so each chart bridges the change. Every rotation appears as a marker on the charts it affects.

When a set retires, its tasks and every past answer to them are published in full, and stay published.

App versions

Each model is measured on two app tracks. "Latest" installs whatever version the vendor currently ships. "Frozen" holds one version fixed and advances it only on a published schedule, set in {{FROZEN_SETTING}}{{FROZEN_VALUE}}. Every move of a frozen version appears as a chart marker.

Statistics

A change is called only when it clears the statistical rule published, dated, in the public repository before any data existed: stats/RULE.md. Every chart shows a confidence band, and anything inside it reads "within normal variation". Each model is compared against its own launch week: its first 7 days after release, pooled and then frozen. Day one is shown as its own point.

Series are never combined: each app, model, effort level, access path and app track is its own line.

Cost

Runs on the subscription path (signed in with a paid plan rather than an API key) carry no cost figure, because a flat monthly plan has no per-run price. Only API-key runs show a cost.

What no outside benchmark can rule out

Special handling based on a lab recognizing the tasks' content cannot be ruled out by any outside benchmark, this one included. A lab that recognizes the tasks could treat them differently from ordinary use. Running from many contributors' accounts and rotating the tasks limits this; nothing eliminates it.

Chart markers

Markers come only from official sources and are added automatically: app releases from each vendor's release feed, model releases from each lab's announcements, incidents from each lab's status page, frozen version moves, task rotations, a lab's own public statements, and model retirement. None is editorial and none is submitted by the community.

Checking a result yourself

The standalone verifier in the public repository (tools/verify) checks any published run's signature and recounts its score from the signed per-task results, without contacting this site. For runs whose task set has retired, it also regrades every answer against the now-public checks, and says which of the two it did.
