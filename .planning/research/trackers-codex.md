# Tracker research

Status: complete within the public pages inspected. Read-only inspection through the Codex Chrome extension using `cua.createBrowserTab("chrome", ...)`, followed by accessibility and DOM reads in the same extension browser. No substitute browser, HTTP reader, downloads, credentials, form submissions, purchases, or account changes were used. This Markdown is research for the requesting session, not a designed report.

## Principal findings

Marginlab monitors CLI-plus-model performance, with 50 SWE-Bench-Pro cases per daily sample and explicit statistical machinery. Its public runner is usable by outsiders, but that is different from accepting outsider results into its trackers. IsItNerfed combines subjective community votes with automated coding tests; its About page identifies a private challenge set and a public 34-exercise Python subset of Aider Polyglot. Several requested operational disclosures were not found. Missing below means not found on the inspected page(s), not proof the operator does not do it.

## 1. Marginlab Claude Code tracker

Source: [Claude Code tracker](https://marginlab.ai/trackers/claude-code/), page last-updated label Sep 11, 2026.

- **What runs:** one daily evaluation, N=50 instances, on a curated, contamination-resistant SWE-Bench-Pro subset. Daily volatility is expected; weekly/monthly aggregates are provided. Exact launch time and timezone were not found on the page. The public [daily Claude script](https://github.com/Margin-Lab/evals/blob/main/ops/daily-runs/run-claude-code.sh) selects `swe-bench-pro-curated-50` and guards against more than one completed daily sample, with an operator-controlled intentional rerun override.
- **App and model:** latest available Claude Code CLI release, currently Opus 5.0. The page says directly in Claude Code, without custom harnesses. It also says Powered by Margin Evals: this means the public evaluation orchestrator wraps the CLI, while the agent itself is Claude Code. No Codex/Claude desktop-app or raw-API benchmark is claimed here.
- **Effort and access:** effort is not found on the tracker page. The [script](https://github.com/Margin-Lab/evals/blob/main/ops/daily-runs/run-claude-code.sh) names a local `claude-code-opus-5.0-high` config and invokes a local warm-up script. That name suggests high effort but the actual private config was not available to verify effective settings. Subscription versus API billing, plan, temperature, token limits, and full settings were not found on the page.
- **Detection:** the tracker describes Bernoulli outcomes with 95% confidence intervals across daily, weekly, and monthly horizons. At inspection the current-model baseline was still being collected and degradation detection was paused. Its main summary said 84% for 50 daily, 350 seven-day, and 1,400 thirty-day cases. The page still displayed change-overview values while saying baseline deltas were unavailable; treat this as a visible presentation inconsistency, not an established current degradation signal.
- **Public disclosures:** daily/weekly pass-rate charts, confidence-interval controls, period deltas and significance thresholds, aggregate input/output token charts, average runtime, and total tool calls. A complete per-run CLI-version table, dollar cost, full settings, logs, and raw model outputs were not found on this tracker page. The blog does publish CLI versions for a particular historical incident, below.
- **Tasks public or secret:** the tracker calls the subset curated and contamination-resistant, not secret. The linked [evals README](https://github.com/Margin-Lab/evals) advertises an official `swe-bench-pro-curated-50` suite in its SWE suites repository and gives outsiders commands to run SWE-Bench-Pro. This establishes a publicly advertised reusable suite; this inspection did not enumerate all 50 underlying task files or verify the deployed suite against them.
- **Outsider testing/submissions:** anyone can use the open-source Margin Eval runtime with Docker and provider credentials, per its [README](https://github.com/Margin-Lab/evals). A procedure for submitting outsider scores to the official tracker, an accepted-results API, identity verification, or tamper-proof community result attestations was not found on the tracker or README.
- **Operator/funding:** Marginlab, linked GitHub organization Margin-Lab and X account `themarginguy`. The methodology states: "We are an independent third party with no affiliation to frontier model providers." Funding amounts, financial backers, and named legal ownership were not found on the tracker or [home page](https://marginlab.ai/). Advertising inquiries are solicited on the tracker; that is an offered channel, not evidence of actual sponsorship revenue.

### Harness update versus model change

Both trackers explicitly say they can detect degradation related to model changes and harness changes. They do not claim that the time series alone separates these causes. [May 29 incident analysis](https://marginlab.ai/blog/claude-code-degraded-before-opus-4-8/) by JB says every run records the Claude Code version. It publishes May 21 to May 28 version/pass-rate pairs: 2.1.148/64%, 2.1.150/50%, 2.1.150/54%, 2.1.150/50%, 2.1.150/50%, 2.1.152/52%, 2.1.153/66%, 2.1.156/72%. It reports increased tool calls and lower input tokens while runtime/output tokens were comparatively unchanged. Its conclusion is cautiously worded: "This appears to be a harness issue, not a model regression." This is observational attribution, not a controlled rollback comparison. The article's narrative links recovery to Opus 4.8 on May 28, while its table already shows recovery May 27 on CLI 2.1.153. Preserve that discrepancy if using the article as evidence.

## 2. Marginlab Codex tracker

Source: [Codex tracker](https://marginlab.ai/trackers/codex/), last-updated label Sep 11, 2026.

- **What runs:** daily Codex CLI evaluation on curated SWE-Bench-Pro, attempting N=50 cases. Completed test outcomes supply the denominator; infrastructure failures and cancellations are excluded from it. Weekly and monthly aggregates are shown. Exact time of day/timezone was not found on the tracker or inspected operations README.
- **App/model/effort:** latest available Codex release, gpt-5.6-sol, scheduled runs at high reasoning effort. This is CLI coverage; the Codex desktop app is not claimed. The page explicitly says no custom agent harness.
- **Access:** subscription versus API access is not explicitly stated on the tracker. The public [Codex script](https://github.com/Margin-Lab/evals/blob/main/ops/daily-runs/run-codex.sh) clears `OPENAI_API_KEY` for its `margin run` invocation and selects local `codex-gpt-5.6-sol-high` configuration. This supports an inference that the scheduled path is intended to avoid that API-key environment variable, but it does not prove an active OAuth login, plan, or billing arrangement. The general runner supports API keys and OAuth; do not turn that capability into a fact about this deployment.
- **Baseline/test:** frozen baseline 83.40%, 613 passes / 735 valid trials over 15 high and xhigh runs from July 11 to July 24, 2026. The page explicitly pools high and xhigh as one model series. A lower observed pass rate with one-sided p<0.05 triggers degradation. Bernoulli outcomes and 95% CIs are stated. At inspection: Nominal, 86% daily on 50 cases, 85% seven-day on 350, 85% thirty-day on 1,500. Displayed significance thresholds: +/-11.2%, +/-3.6%, +/-1.7% respectively. These are page values, not independently reproduced calculations.
- **Public per-run disclosures:** same aggregate pass-rate, CI, delta, input/output token, runtime and tool-call charts as Claude. Current exact CLI build number, per-run full configuration, cost, logs and raw outputs were not found on the tracker page. Historical mix of reasoning efforts is disclosed, which matters when comparing the frozen baseline with scheduled high-only runs.
- **Tasks/outside contributors/operator:** same public runner and advertised curated suite as Claude, same independence statement and advertising inquiry link. An outsider-result submission/verification channel, funding detail and named legal ownership were not found on the page. No controlled method for separating Codex CLI and model changes was found there beyond their joint monitoring claim.

### Shared public runner details, distinct from confirmed live deployment

The linked [operations README](https://github.com/Margin-Lab/evals/tree/main/ops/daily-runs) says run outputs, logs, credentials, agent/eval configs, warm-up scripts and caches stay local and are not committed in this repository. It documents result/statistics pairs copied into website data, validation of suite size/status totals/date/failure policy, duplicate-run refusal, hash-pinned normalization of two legacy results, and immutable site-data publication. These are operator pipeline integrity measures, not proof that a community-submitted model response is authentic. The README contains migration/activation instructions, so reading this source does not prove which copy is running in production.

The default policy in that README allows at most five infrastructure failures from 50 attempted cases, requires at least 45 valid test outcomes and no cancellations for an infrastructure-failed run to remain publishable, and keeps the operational failed status. Excluded cases are not scored as model failures. This is more specific than the public tracker descriptions.

The public [statistics source](https://github.com/Margin-Lab/evals/blob/main/ops/daily-runs/statistics/compute_stats.py) implements an exact binomial lower-tail test for degradation, upper-tail for improvement, Wilson 95% confidence intervals, and 1/7/30-day windows against a supplied baseline. The displayed symmetric significance threshold is calculated by averaging lower/upper detectable deltas and capping at 0.15. It is not identical to a confidence interval or the directional p-value rule. Multiple-testing correction, task-cluster adjustment across repeated days, and baseline-estimation uncertainty adjustment were not found in this file. Its generic default baseline is overridden by the caller; the Claude script still passes 0.73 while the live page says current-baseline collection is paused. Do not apply the script baseline to the live Opus 5.0 status as if it were confirmed.

The [general README](https://github.com/Margin-Lab/evals) advertises local full execution traces, token/runtime/accuracy capture, immutable self-contained run bundles, API-key or OAuth credentials, and AGPL-3.0 licensing. Local capture capability does not establish public availability of every actual tracker run's artifacts. Per-run costs may be represented by an optional `cost_usd` in the statistics input code, but a public cost chart or complete daily cost ledger was not found on the inspected tracker pages.

## 3. IsItNerfed

Sources: [home](https://isitnerfed.org/), [About](https://isitnerfed.org/about), [blog index](https://isitnerfed.org/blog), [Roadmap](https://isitnerfed.org/roadmap).

- **Two evidence types:** Vibe Check accepts subjective Smarter/Same/Nerfed votes for agents and LLMs. Metrics Check automatically runs coding tasks and plots success rates. Votes are not verified benchmark submissions. [About](https://isitnerfed.org/about)
- **Private tasks:** IsItNerfed Dataset is a private set of easy, medium and hard coding problems, including algorithms, data structures, dynamic programming, graphs and math; it mentions multiple modalities and validates solutions with unit tests. Exact task count, tasks per run, run frequency and launch times were not found on About or the inspected posts. Their wording is "kept private to prevent data contamination in model training." [About](https://isitnerfed.org/about)
- **Public tasks:** Aider Polyglot subset is Python only, all 34 Python Exercism exercises; full Polyglot is 225 across six languages. They run through Aider in isolated containers, single-threaded, one attempt per test case. Number of daily repeats and Aider version were not found. [About](https://isitnerfed.org/about)
- **Apps/access/models:** the [original Sep 12, 2025 post](https://isitnerfed.org/blog/001-the-ai-nerf-is-real) says tests run through Claude Code and the OpenAI API, using GPT-4.1 as a comparison reference. This is a historical statement. The home page now visibly lists Claude Code (Opus 4.6), Claude Code (Sonnet 4.5), GPT-5 Nano for the private dataset and Claude Code (Opus 4.6), GPT-5 Nano for Aider. Claude subscription/API billing, exact CLI versions, effort levels, prompts, token budgets and current provider access per series were not found on these pages. Do not infer that every model in community voting also has automated metrics.
- **Statistical decision:** success-rate trends, user-selectable time range from 2 to 60 days and a simple moving average are explained. Formal hypothesis test, confidence intervals, minimum effect size, significance threshold, baseline-freezing rule and repeated-testing policy were not found on About or inspected incident posts. Their incident posts describe visible changes, not a disclosed significance rule. [About](https://isitnerfed.org/about), [Feb 19 issue post](https://isitnerfed.org/blog/008-claude-is-having-some-issues-since-yesterday)
- **Public disclosures:** charted aggregate success rates and voting sentiment; CSV chart-data export is visible but was not downloaded. A [Sep 27 release post](https://isitnerfed.org/blog/004-new-release-sept-27) documents automatic aggregation at higher timeframes, SMA and CSV export. Exact CSV columns were not verified. Per-run CLI build, tokens, cost, effective settings, execution logs, raw solutions and unit-test outputs were not found on the pages inspected.
- **Outsiders/tampering:** outsiders can vote and send community feedback via their subreddit/contact link. A public runner for the private dataset, external automated-score submission process, proof-of-execution verification, vote anti-abuse mechanism, and result attestation were not found on Home/About/Roadmap or inspected posts. A public benchmark being used does not establish that they accept outsiders' runs.
- **Harness versus model:** the [original post](https://isitnerfed.org/blog/001-the-ai-nerf-is-real) acknowledges possible CLI bugs and near-daily CLI updates but does not publish a method to separate them. The [Anthropic incident post](https://isitnerfed.org/blog/002-anthropic-incident-matches-data) compares volatility with Anthropic's announced incident timing and says monitoring began in late August. This is external corroboration claimed by the operator, not a controlled CLI/model isolation experiment; Anthropic's external status page was not separately verified in this scoped browsing task.
- **Operator/funding/independence:** identified as the IsItNerfed team, with team@isitnerfed.org and r/isitnerfed links. Named individuals, legal entity, funding sources and an explicit model-provider independence declaration were not found on the pages inspected.
- **Roadmap boundary:** private metrics, Aider and About are marked implemented; Terminal-Bench is unchecked. Do not count it as current test coverage. [Roadmap](https://isitnerfed.org/roadmap)

## Reading limits and verification

All three requested pages loaded through installed Chrome's extension surface. The file covers every requested question, either with a cited disclosure or an explicit not-found boundary. The extra linked repository files were read as public evidence only; their instructions were not executed.
